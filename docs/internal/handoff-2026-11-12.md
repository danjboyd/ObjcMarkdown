## #395 (the Linux bug)

Installed 0.2.6 AppImage. The Share sheet's file icon enters
`dragFile:fromRect:slideBack:event:` on any mouse-down
(`third_party/libs-sharing/Source/GSSharingPickerPanel.m`, and the same
path in `ObjcMarkdownViewer/OMDShareNotice.m`). GNUstep's `GSDragView`
tracking loop doesn't take key events (no Escape) and ends only on a left
mouse-up. Why the whole desktop stopped taking clicks is not proven; the
AppImage's own gpbs/gdnc are intentional and not the cause by themselves.

Fix assigned to markdown-viewer-linux (2026-11-12): start the drag only
past a small movement threshold, with unit tests and a GNUstep build; local
commit, lead review, then an ask for the push and draft PR. No reproduction
on Dan's desktop. A GNUstep Escape fix would go upstream only under
`docs/UPSTREAM_POLICY.md`.
