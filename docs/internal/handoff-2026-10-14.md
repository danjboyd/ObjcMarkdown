The four Windows updater bugs fixed in gnustep-packager #20/#21, all found
in #118 round 3 on a clean VM:
1. `PATH` looked up case-sensitively (Windows calls it `Path`), so certutil was never found: every update "could not be hashed". certutil and msiexec now come from `GetSystemDirectoryW`.
2. GPUpdaterUI alerts drew blank on win32: `runModal` entered from a `performSelectorOnMainThread:` callback never paints. All alerts now go through `-_presentAlertDeferred:withObject:` (afterDelay:0).
3. msiexec 1619: forward-slash paths lose the drive. Paths are converted to backslashes.
4. No relaunch, state stuck at "applying": Restart Manager kills the helper (it runs from the install folder). The helper now writes `apply-msi.cmd` into the state dir and starts it detached through System32 `cmd.exe` (whose own path must be backslashed, or cmd reads `/system32` as `/s /c`). The script runs msiexec, writes the final state, relaunches through the launcher on 0/3010, writes `completed` without relaunch on 1641, `failed` otherwise.
Verified on the VM before merging: the full update from a TEMP with a space (completed, relaunched, no console), and DisableMsi=1 (failed 1625, no relaunch).

## Draft release notes (0.2.2)

> **Updating from 0.2.0 on Linux and Windows:** 0.2.0's updater can't install this release (it can't download from GitHub's release servers, and on Linux it also stops when the AppImage closes). Install 0.2.2 by hand once; later updates install themselves.
> - AppImage: 0.2.0 offers this update but can't install it; after *Restart and Install* the app closes and stays on 0.2.0. Download `ObjcMarkdown-0.2.2-linux-x86_64.AppImage` and replace your copy.
> - Windows: download `ObjcMarkdown-0.2.2-win64.msi` and run it; it replaces 0.2.0.
> - macOS updates itself as usual; Flatpak updates come through Flatpak.
>
> **Fixed:** launching in Split mode or opening a window tab no longer crashes on Linux (#120); closing a window tab no longer crashes, and on macOS closing a tab with unsaved changes no longer hangs (#126); updates download on Linux and Windows and must carry the project's Ed25519 signature; the Windows updater relaunches through the launcher (#117); Linux shortcuts use Ctrl as the menus show; the AppImage follows dark mode, high contrast and Large Text; Export as PDF, HTML, DOCX and ODT and Print work in the Linux packages; About shows the right version; large documents open much faster on Linux and Windows (#94); Open is one toolbar control with recent files on its arrow; on Windows, the menus are reachable from the keyboard (Alt, F10, access keys; #115) and the window title shows the document name with an unsaved marker (#116), with WinUITheme 0.1.0-alpha3; the Windows updater's alerts draw, and its download check and install work for a normal (non-administrator) user.
>
> **Known issues:** Flatpak doesn't follow dark mode or Large Text yet (the theme needs the Settings portal, #124); the explorer is squeezed in a narrow window; Windows printing goes through a PDF in the browser (#82); a very large document in Split can keep the Windows window busy for about a minute (#121); on Windows Server, in-app updates need an administrator or the DisableMsi policy set to 0, otherwise the update fails, the app stays closed, and you can install the MSI by hand. If a Windows update fails for any reason, start Markdown Viewer again; it does not yet say why.

## Things to know

- **Approvals.** Dan approves every push, merge, tag, release deletion and lease destroy, in the session that does it; a relayed OK doesn't count. The coordinator passes decisions along as information only.
- **Sessions.** macOS (this repo, coordination, CI dispatch, tags, #112), Linux (#114, all otvm leases incl. Windows ones), Windows (#118, MSI, re-vendoring), gnustep-packager (updater fixes upstream). Remote Control peers can restart and lose context: re-send the full context, not a reference to earlier messages.
- **CI is not proof for Windows updater code.** gnustep-packager's Pester test of the helper is skipped on Windows CI (the helper only builds in MSYS2 CLANG64). Hold merges of Windows updater changes for a VM run.
- **Installed helper does the update.** A fix to the updater only helps updates *from* a build that has it.
- **Dispatched packaging runs** need `-f version=...` or they package as the manifests' stale `0.1.1-rc2`.
- **Line endings.** Commits made on Windows have turned LF into CRLF before; check `git diff --stat` for whole-file rewrites.
