## Draft release notes (0.2.2)

> **Updating from 0.2.0 on Linux and Windows:** 0.2.0's updater can't install this release (it can't download from GitHub's release servers, and on Linux it also stops when the AppImage closes). Install 0.2.2 by hand once; later updates install themselves.
> - AppImage: 0.2.0 offers this update but can't install it; after *Restart and Install* the app closes and stays on 0.2.0. Download `ObjcMarkdown-0.2.2-linux-x86_64.AppImage` and replace your copy.
> - Windows: download `ObjcMarkdown-0.2.2-win64.msi` and run it; it replaces 0.2.0.
> - macOS updates itself as usual; Flatpak updates come through Flatpak.
>
> **Fixed:** launching in Split mode or opening a window tab no longer crashes on Linux (#120); closing a window tab no longer crashes; updates download on Linux and Windows and must carry the project's Ed25519 signature; the Windows updater relaunches through the launcher (#117); Linux shortcuts use Ctrl as the menus show; the AppImage follows dark mode, high contrast and Large Text; Export as PDF, HTML, DOCX and ODT and Print work in the Linux packages; About shows the right version; large documents open much faster on Linux and Windows (#94); Open is one toolbar control with recent files on its arrow.
>
> **Known issues:** Flatpak doesn't follow dark mode or Large Text yet (the theme needs the Settings portal); the explorer is squeezed in a narrow window; Windows printing goes through a PDF in the browser (#82); a very large document in Split can keep the Windows window busy for about a minute (#121).

## Things to know

- **Approvals.** Dan approves every push, merge, tag and release deletion. The Linux and Windows sessions want his OK in their own session; a relayed OK doesn't count there. The macOS session acts on Dan's OK given in its session.
- **Who does what.** macOS: coordination, pins, merges, CI, tags, #112. Linux: #114, creates the Windows lease (otvm runs on the Linux operator machine), Linux package fixes. Windows: #118, the updater and MSI. Adwaita fixes go through the `plugins-themes-adwaita` session.
- **Line endings.** Commits made on Windows have turned LF files into CRLF (29c76f7 fixed the updater's). Check `git diff --stat` for whole-file rewrites before pushing.
- **Packager CI.** gnustep-packager's `windows-validation` fails on its own main too: its gnustep-cli-new bootstrap download (`curl ... gnustep-bootstrap.sh`, exit 4) fails before anything is built. Judge PRs by `linux-validation` and the Windows session's own Pester run until that is fixed.
- **MSI versions.** The packager makes ProductVersion from the first four numbers (rc1 0.2.2.1, final 0.2.2.0). Windows Installer ignores the fourth field when upgrading, so all of 0.2.2 is one version; `AllowSameVersionUpgrades="yes"` (in 84694a3) is what lets rc -> rc -> final upgrade.
- **Dispatched packaging runs** without `-f version=...` package as `0.1.1-rc2` (the manifests' own version); tag runs use the tag.
- **Mac Quick Look.** Two stale registrations from earlier update tests (0.1.1 and 0.2.1, in other sessions' scratch folders) may shadow the installed one; `pluginkit -r <path>/Contents/PlugIns/MarkdownPreview.appex` removes each.
