## Architecture added in this batch

Library (`ObjcMarkdown/`):

- **Parsing**: vendored cmark-gfm 0.29.0.gfm.13; always parse through
  `OMGFMParseDocument()`.
- **Renderer split (#21)**: `OMMarkdownRenderer.m` (class, blocks,
  inlines, final passes) plus `...Source.m`, `...Code.m`, `...Images.m`,
  `...Math.m`, `...Tables.m`, `...Mermaid.m`. `OMMarkdownRendererInternal.h`
  (not installed, `#pragma GCC visibility push(hidden)`) holds
  `OMRenderContext` and every helper used across files, grouped by defining
  file. A new cross-file helper: drop `static`, add its prototype there.
- **Rendered objects (#27-#29)**: math, diagrams, images and drawn tables
  are attachment characters carrying `OMRenderedObjectAttributeName`
  (`OMRenderedObject`: kind, source, markdown, source line range, exact
  source range). Pending objects are resolved after rendering in
  `OMResolvePendingRenderedObjects` (`...Source.m`).
- **Block IDs (#11)**: `OMBlockSignatureIndex` (FNV-1a per normalised line,
  polynomial prefix hashes), shared with the viewer's `OMDPreviewSync`.
- **Text tables (#15)**: tables are text, one paragraph per visual line,
  cells separated by tabs at per-line left tab stops (GNUstep supports only
  left tabs), cells wrapped by the renderer. `OMTextTableAttributeName`
  (an `OMTextTable`: column edges, colours, Markdown, rendered object) and
  `OMTextTableRowAttributeName` mark the text. `OMStrikethroughLayoutManager`
  draws row backgrounds under the selection and rules over it. Tables keep
  the drawn attachment only when `allowTableHorizontalOverflow` is set.
  Cells render the inlines cmark-gfm parsed (so `\|` and reference links
  work).
- **Links (#20 fixes)**: destinations are escaped like cmark-gfm's
  `houdini_escape_href` before `NSURL` (`OMEscapedURLString`), and anything
  with a URI scheme never falls back to a file path. Allowed link schemes:
  file, http, https, mailto.
- **Mermaid (#18)**: `OMMermaidFlowchart` (parser), `...Layout` (ranked
  layout with waypoints routing long/back edges), `...Drawing`. ER diagrams
  as before. Diagnostics are captions under the source code box.
- **Alerts (#13)**, **emoji shortcodes and link tooltips (#17)**, **heading
  anchors and outline (#14)**, **typography (#16)**, **dark theme (#2)**,
  **strikethrough drawing (#4)**.

Viewer (`ObjcMarkdownViewer/`):

- **Header bar (#23)**: `MarkdownViewerInfo.plist` sets
  `GnomeThemeMenuStyle = primary` and `GnomeThemeHeaderBarToolbar = YES`.
  Off Windows (`OMDUsesCompactToolbar()`), the toolbar is ToggleExplorer,
  OpenDocument, SaveDocument, flexible space, ModeControls (Vim status label
  + Read/Edit/Split). Windows keeps the old PrimaryActions/ZoomControls
  toolbar and its menu bar.
- **View menu (#25)**: modes, Split Sync, sidebars, formatting bar,

## GNUstep behaviour to remember

- The typesetter ignores `paragraphSpacing`, `paragraphSpacingBefore` and
  `lineHeightMultiple`; only `minimumLineHeight`/`maximumLineHeight` and
  `lineSpacing` (added below the line) work. Text sits at the bottom of a
  line taller than its font. Block gaps are blank lines sized by
  `OMSizeBlockGaps`.
- `NSTextTable`/`NSTextBlock` exist but are not laid out.
- `NSBaselineOffsetAttributeName` is applied upside down; use
  `NSSuperscriptAttributeName`. Strikethrough is accepted but never drawn
  (hence `OMStrikethroughLayoutManager`).
- Only left tab stops. Tab and indent positions are in text-container
  coordinates; line fragment padding is outside them.
- `colorWithAlphaComponent:` returns self for named system colours (convert
  to RGB first). Characters beyond the BMP and colour emoji can't be drawn.
- `NSTextView -rightMouseDown:` builds its own menu without asking
  `-menuForEvent:` (OMDTextView overrides both).
- The Adwaita theme fixes the colour scheme at launch.
